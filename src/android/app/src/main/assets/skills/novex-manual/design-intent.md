# 设计本意

这一章记录 Novex 交互行为的**设计意图**——界面"应该"是什么样。实际表现和这里不一致，就是缺陷，可以直接骂；这里没写的，以常识和主流聊天软件惯例为准。

## 阅读与沉浸

- **深度阅读模式**：点消息区空白处，顶栏和浮动按钮淡出，专心读内容。恢复方式只有两种：再点一次空白处，或返回手势。**滑动消息不唤回**——读的时候翻页是阅读的一部分，不是退出信号。
- **滚动不抢视口**：你停在哪就留在哪。流式回复、分支切换、重试，都不该把你甩到别处。

## 分支与重试

- **重试 = 同槽位再生**：对一条 AI 回复点重试，新回复作为它的兄弟分支生成，旧回复保留、随时可切回。重试的目标是"这条回复所在的回合"，按消息的真实父子关系定位——绝不挂到更早的回合上。
- **分支切换器**：每条 AI 回复下方固定一个（`1/1` 也显示），告诉你这里有几个版本、当前是第几个；没有歧义、位置恒定。**人类输入不挂切换器**——编辑过的旧提问走「后续分支」入口回看，不占每屏的位置。
- **浮动导航钮**：上方的钮按回合向上走（以你的发言为锚点，一次一跳），下方的钮直接回最新。图标配语义：向上走一格 ≠ 回顶部。
- **双击回顶/回底**（规划中）：消息区双击顶部回最早、底部回最新。与分支箭头无冲突——双击发生在空白区，快速连点箭头发生在按钮上。

## 执行过程

- **一个回合一张工作卡**：同一回合的思考、工具调用、过程文字折叠成一条「本轮 N 步」，钉在回答之前，正文不被过程块打断。
- **过程按真实顺序折叠**：如果回复发出后模型又开始新一轮思考-执行，新过程从回答**之后**另起折叠位继续向下——绝不允许长回回答上方，把「思考-执行-回复-思考-执行」错排成「思考-执行-思考-执行-回复」。

## 界面渲染

- **注册即资产**：AI 注册过的前端件是持久资产，不是写在某条回复里的装饰。重试、编辑、换分支之后它都在，后续只更新数据。（详见 `frontend-widgets.md`）
- **加载有进度，落地不跳变**：HTML 件加载期间给小进度条——做完了就快速跳满，做得慢在尾段减速、不装死；渲染完成时向下温柔展开，不整屏跳变。

## 原则

- 界面变化**可预期**：同一个动作永远产生同一种结果；用户不看教程也能猜对每个钮的作用。
- 已存在的操作入口**不做不可见的重定向**：按钮在哪、管哪条消息，必须一眼可知。
