# 设计本意

这一章记录 Novex 交互行为的**设计意图**——界面"应该"是什么样。实际表现和这里不一致，就是缺陷，可以直接骂；这里没写的，以常识和主流聊天软件惯例为准。

## 阅读与沉浸

- **深度阅读模式**：点消息区空白处，顶栏和浮动按钮淡出，专心读内容。退出方式只有两种：再点一次空白处，或返回手势。**滑动消息不唤回**——读的时候翻页是阅读的一部分，不是退出信号。沉浸态下的返回手势**先退出阅读模式**（界面回来），再按一次才返回上一级——模式拦截返回，不吞导航。
- **滚动不抢视口**：你停在哪就留在哪。流式回复、分支切换、重试，都不该把你甩到别处。

## 分支与重试

- **重试 = 同槽位再生**：对一条 AI 回复点重试，新回复作为它的兄弟分支生成，旧回复保留、随时可切回。重试的目标是"这条回复所在的回合"，按消息的真实父子关系定位——绝不挂到更早的回合上。
- **分支切换器**：每条 AI 回复下方固定一个（`1/1` 也显示），告诉你这里有几个版本、当前是第几个；没有歧义、位置恒定。但只对真正渲出可见内容的回复显示——零内容的幻影行不挂。**人类输入不挂切换器**。发送中断/重试留下的旧线由恢复路径自动归位；回复落地后随时可用它自己的翻页器换线。
- **浮动导航钮**：单击按回合走——上钮跳到上一条你的发言、下钮跳到下一条（可快速连点，不限速）。**长按拖动 = 拉伸跳端**：按住钮稍作停留再往上/下拖，出现拉伸方向指示，松手即到顶/到底——两个钮都支持，与单击互不冲突。图标配语义：走一格的符号不许画成回端点。

## 执行过程

- **一个回合一张工作卡**：同一回合的思考、工具调用、过程文字折叠成一条「本轮 N 步」，钉在回答之前，正文不被过程块打断。
- **过程按真实顺序折叠**：如果回复发出后模型又开始新一轮思考-执行，新过程从回答**之后**另起折叠位继续向下——绝不允许长回回答上方，把「思考-执行-回复-思考-执行」错排成「思考-执行-思考-执行-回复」。

## 界面渲染

- **注册即资产**：AI 注册过的前端件是持久资产，不是写在某条回复里的装饰。重试、编辑、换分支之后它都在，后续只更新数据。（详见 `frontend-widgets.md`）
- **未写完的界面不露源码**：流式输出中途，`novex-def`/`novex-use`/`html` 围栏还没闭合时不渲原文——只露装载占位。界面围栏不是给用户读的代码。
- **加载有进度，落地不跳变**：HTML 件加载期间给小进度条——做完了就快速跳满，做得慢在尾段减速、不装死；渲染完成时向下温柔展开（窗口下沿从上往下扫，内容本体不缩放、不整体淡入），不整屏跳变。
- **对话内的界面做小**：对话里的界面以图片加少量组件为限，按顺序选——已注册的件 → 系统预置件 → 新注册一个件 → 自由 html（只给小游戏、画布这类）；拿不准要不要界面，就只写正文。件造一次，之后只填数值，不为每颗子弹重新造枪。

## 前端作品（全屏）

> 舞台协议 v0.3 已在手机端落地（帧推送、`input:"own"` 输入层、transcript/cast/choices/deltas、查证轮、ready 超时与崩溃逃生）。字段与出站契约细节见 `frontend-widgets.md`「舞台协议」节；体检入口在聊天菜单「舞台自检」。

- **作品是什么**：创作者做好的一整套全屏界面（视觉小说、仿聊天软件、朝堂沙盘……），开启后 AI 的全部表现都由它呈现。作品做一次，诺文每轮把内容交给它，它负责画；用户在作品里的操作再传回诺文。AI 不管界面怎么画，照常写故事——同一个故事换一套作品，就是另一种呈现。
- **作品是卡的一部分**：世界卡、角色卡都能带作品，随卡分享、可二创。一局里有多个作品时用户自己切换。世界作品可以按挂载的角色卡排版（几个人几个头像、谁说话亮谁）；卡与卡对不上由创作者自己统一，诺文只保证不黑屏——缺头像显示名字首字，缺颜色用中性色。
- **作品可以自带输入层**：作品能自己画输入框，替代原生输入栏。**发送只认用户真实的点击**——脚本不能替用户发消息，没有自动发送（倒计时代发、NPC 自动开口都不做，避免意外扣费）。按钮放不放、放多少，是作品自己的设计取舍。
- **键盘交给系统**：用系统输入法（游戏模式由输入法自己提供），诺文不自造键盘。键盘弹出时作品区平滑抬升、不遮挡输入处，并把键盘高度告诉作品；骨架模板默认把回车设为"发送"。
- **全屏下没有原生选项条**：模型给的选项作为数据交给作品，作品用自己的样式画或不画。作品内部的点击（翻页、切视图、展开卡片）不经过诺文，不受任何限制。
- **作品里不重试、不编辑**：作品只负责玩。原生对话始终在下层，退出全屏就能看到模型原文、检查自己发出的每一句话，并在那里重试、编辑、切分支——原生层是记录，也是逃生口。
- **状态是真相，作品只显示**：血量、钱粮、档案等数值只能由 AI 加规则改动，作品读取并显示，不能自己写。档案和本局状态一样按分支保存——重试或切分支后，作品看到的一定是这条分支的事实。
- **坏了也给你看**：作品崩溃或卡死，自动退回原生对话；协议块永远不裸露给用户。
- **一个模型演到底**：多角色由同一个模型扮演，不做多 agent——结果表现好，多 agent 多半是伪命题。台词的说话人用"行首 + 本局角色名册里的名字 + 冒号"标出；句中的"@某人"、名册外的名字都按普通文字处理。

## 电脑工坊与手机戏台

- **电脑做，手机玩**：电脑上的模拟器复刻手机的运行环境——电脑上看到什么，手机上就得到什么。前端是网页，手机端不需要重新编译。
- **兼容原则**：电脑向手机妥协——手机做不到的写法电脑上不许用，模拟器把它标红；手机向电脑看齐——电脑侧定义的协议，手机必须补齐。两端表现不一致，按手机侧缺陷处理。手机系统 WebView 过旧时只提示"作品可能显示不全"，不拦截使用。
- **做作品不碰代码**：从骨架模板起步（聊天风、视觉小说风、终端风……），用对话让 AI 改外观，在模拟器里用假剧本预演（旁白、台词、出图、选项、数值变化、切分支、报错），满意后存进卡。
- **一致性靠体检**：同一个体检页面在电脑模拟器和真机上各跑一遍，逐项比对；报告不一致就是缺陷，不靠肉眼"差不多"。

## 原则

- 界面变化**可预期**：同一个动作永远产生同一种结果；用户不看教程也能猜对每个钮的作用。
- 已存在的操作入口**不做不可见的重定向**：按钮在哪、管哪条消息，必须一眼可知。
