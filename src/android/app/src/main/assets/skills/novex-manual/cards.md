# 卡片体系：世界 / 角色 / 文游

**文游就是卡，卡就是文游。** 文游无非是一张加了规则的世界卡——多了开局资料、每轮规则、本局状态和存档机制。世界卡、角色卡、文游卡都是同一棵"模块树"，区别只在装了什么模块、以什么方式进入对话。

## 建卡与启动

- **建卡**：`create_card`/`create_card_bulk` 建 WORLD/CHARACTER 卡；文游卡在卡里加规则模块即成。用户说"帮我做个世界/角色/游戏"时走建卡通道。
- **启动文游**：这是**原生动作**——用户在「会话设置 → 活动文游 → 选择并启动文游」发起，模型端没有启动文游的工具。用户说"开始玩"时引导他点这个入口；文游激活后 `update_playthrough_state`/`save_checkpoint`/`set_player_identity` 等本局工具就位。
- **结束文游**：同样在会话设置——「结束文游并恢复原身份」，保留消息、状态与存档，返回列表不结束文游。

## 卡 = 模块树

模块标签：`routing`（default 开局资料包 / perTurn 每轮 / style 文风 / standby 待命）、`temporality`（constant 可重注入 / snapshot 只随开局）、`use`（触发规则）、`tags`（自由标签；`novex-frontend` = 前端件模块，`novex-skin` = 皮肤模块）。

- **原文导入模块**（整份外部卡原文）：不在开局包内联，逐轮按需分页——模型可 `read_text_block` 续读，`read_card` 看结构。
- 大卡分页工具：`read_card` 读结构目录、`read_text_block` 按块读正文、`skill_read` 读技能文件。

## 模块内容的三种携带方式

每个模块按 `use` 规则决定什么时候进入上下文：

1. **每轮携带**（`use=always`）：无条件注入，适合全局地图/总则这类"模型永远需要知道它存在"的内容。代价是每轮都占上下文。
2. **关键词触发**（`use=keywords`）：本地运行时扫描**最近的可见消息**（用户和模型的发言），命中关键词才注入，没命中不占额度。注意两条边界：只扫可见消息、**不递归**——某模块正文里写的词不会再触发别的模块；每条模块要靠自己标题/关键词被聊到。
3. **不自动携带但可查询**（`use=manual`）：内容落库但永不自动进上下文，用 `read_card`/`read_text_block` 精确回读。适合大部头原文——但注意读取依赖工具调用，工具链弱的模型可能拿不到。

导入的非官方卡/资料默认走关键词档，避免每轮硬塞。

## 背景挂载 vs 管理范围（读懂"只读"）

把卡带进对话有两种互不相同的身份：

- **背景**（会话设置「使用的设定」）：内容给模型当参考/注入材料，**天然只读**——模型看得到但改不了。列表里显示"只读"不是故障，是这张卡此刻只作资料。
- **管理范围**（「可管理的内容」）：允许模型读取并按权限修改原件。"只读"档=能看不能改；"可编辑"档=能改。想把一张背景卡变成可编辑，要在管理范围里把它设为可编辑，不是重新挂背景。

建卡回执纪律：`create_card`/`create_card_bulk` 回 `saved` 就表示真的存进卡库且本会话可管理——之后 `read_card` 说"不在管理范围"是异常，把当前管理目录发给模型让它纠正目标编号，或让用户重新保存会话。

## 改卡工具（要求卡在管理范围）

- **加模块**：`add_module`（单个）/`add_module_bulk`（批量）/`add_child_module`（挂到既有模块下）；`write_module_text` 写正文、`replace_text_range` 局部替换。
- **调结构**：`move_module`（换位）/`place_module`（移到指定父级下）；`rename_card`/`rename_module` 改名。
- **携带规则**：`set_module_options` 调 use/routing/temporality/关键词。
- 编辑以 `draft_version` 乐观锁并发；回执里的版本号照实回传，不要编。

## 附件文档（docx/pdf 等）怎么到达模型

按正文大小自动分三档，不依赖模型自觉调工具：

- **小文档**（约 3 万字符内）：全文直接随用户消息送达，模型当场就能读到。
- **大文档**：自动物化为一张"资料：XX"会话卡挂进背景+管理范围——目录模块每轮常驻（模型始终知道文档里有哪些节），各章节按标题关键词触发注入，`read_card` 也能精确回读。同一文档重复附加不会重复建卡。
- **兜底**：上面两条路都不适用时（快照损坏/旧式会话）回落原回执模式，仍可用 `document_inspect`/`document_read` 分页读取——但这条路依赖工具调用能力。

## 本局状态（update_playthrough_state）

文游进行中的位置/生命/物品/任务等跟踪事实变化时调用：`{key,value}` 写改（同名覆盖）、`{remove:"键"}` 删除。状态只属当前消息分支，切换分支不重新调用。岛屿/前端件可经 NOVEN_FRAME.state 读到这些值。

## 存档（save / saves / load）

用户要求存档调 `save_checkpoint`：通常只传存档名，软件自动保存当前分支消息、采用设定与登记状态，不自行重编剧情或虚构路径。金卡 Save/Saves/Load 对应同一套操作。
